### 2026-07-22 — "This link couldn't be opened": a wa.me link needs the country code, not just digits
PROBLEM: Fadly reported the fee-ask WhatsApp button ("Tanya Yuran & Kekosongan") failing with iOS's "This link couldn't be opened" error, while the main WhatsApp button on the same school worked. His own comparison test (same school, one button works, one doesn't) was the correct diagnostic and pointed straight at the link-building code rather than WhatsApp itself.
WORKED: Traced every wa.me construction in both school.html and index.html rather than fixing only the reported button. Found the real shape of the bug: wa.me requires full international format with NO leading trunk zero ("012 6486 747" must become "60126486747", not "0126486747") -- index.html's main WhatsApp button already had this conversion correct (strip spaces/dashes, then convert a leading +60 or a leading 0 to the 60 country code), but its neighboring fee-ask button used a plain digit-strip with no such conversion, so it silently built an invalid link. Checking the full inventory turned up something worse: school.html had the SAME bug in ALL SIX of its wa.me links, including its own main WhatsApp button -- the correct logic had only ever been applied in index.html, never ported to school.html's copy. Extracted the correct logic into a shared `waNum()` helper in each file (files remain separate per this codebase's architecture, but the duplication risk within a single file is now eliminated) and applied it to every call site, then proved the fix against the exact real phone number from the reported screenshot plus several other formats already present in the live database (dashes, existing +60, already-full-international) to confirm nothing else broke.
FAILED: n/a -- the bug itself was the failure being investigated, not anything attempted and abandoned during the fix.
RULE: When a "same feature, two buttons, one works" bug report comes in, don't stop at fixing the one broken instance -- grep for every other construction of the same pattern in the same file AND its dual-page sibling. The working button next to the broken one is often the reference implementation for the fix, not just evidence something else is wrong. When the correct logic already exists somewhere in the codebase (index.html's waChat here), extracting it into a named, reusable helper prevents the exact "one copy got the fix, the other didn't" failure that caused the bug in the first place.
ROUTED TO: school.html and index.html (waNum() helper, all 7 wa.me call sites); this note, to be merged into learnings-log.md.
